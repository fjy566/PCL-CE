## 修复内容

1. **缓存文件内容丢失**：`HashStorage.PutAsync` 计算哈希后继续从流末尾复制，存入空文件。现在对可定位流重新定位，对不可定位流使用自动删除的临时文件，支持压缩、预先提供哈希及网络式只读流。对象写完并关闭后再发布到正式路径，避免并发读取半成品。
2. **TAR 解压生成空文件**：旧代码遍历到归档末尾后调用 `Reset`，没有重新读取各条目的内容。改为使用 SharpZipLib 的异步接口单遍解压，验证 `.tar`、`.tar.gz`、`.tgz` 中多文件、子目录与空文件的实际内容。流式 TAR 无法预知总长度，进度在开始/完成时报告 0/1。
3. **文本追加失败及编码误判**：首次追加会尝试打开不存在的文件；编码检测的 UTF-8 验证没有读取输入，BOM 的完整数组匹配也会漏判带正文的 UTF-8/UTF-16。现在首次追加可创建文件，保留已有文件编码，支持 BOM、GB2312/GBK 和跨采样边界的 UTF-8，检测后恢复调用方的流位置。
4. **ZIP 进度与取消**：目录条目原先只计入总数、不计入完成数，导致进度不能到 100%。现在统计目录，空归档也报告完成；取消会在创建目标目录/条目前检查。TAR/ZIP 的路径越界拒绝测试继续通过。
5. **缓存过期清理错误**：SQLite 将 ISO 8601 文本与另一种时间文本格式比较，部分查询还丢弃小数秒或忽略传入的 `now`。现在通过 `julianday` 比较，使用调用者提供的时间，覆盖启动清理、过期删除和统计。
6. **测试运行环境**：补齐 EventBus 生命周期上下文、WPF pack URI 注册及 SQLite 连接池清理。只清理每个测试数据库对应的连接池，不清空其他数据库连接池。保留原有断言和失败测试。

未修改桌面 UI 产品代码、账号验证、地域策略、授权要求或远端服务配置。

修复防止之后的缓存写入丢失内容；旧版本已经写入的空缓存对象不会自动恢复原始内容，需要清理受影响缓存并重新获取。GB2312/GBK 等无 BOM 编码采用采样推断，无法保证任意混合编码或二进制文件都能准确识别。
